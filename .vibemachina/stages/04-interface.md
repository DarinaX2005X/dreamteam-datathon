# 04 Интерфейс: рабочее место проверяющего, лист проверки, нормы и лендинг
Status: active

Цель этапа: проверяющий проходит весь путь от загрузки записи до решений по эпизодам и листа проверки в цельном, отзывчивом интерфейсе, а новый посетитель за секунды понимает продукт на лендинге. 04.1 закладывает общие токены, примитивы, каталог строк и клиент API. 04.2, 04.3 и 04.4 строят свои экраны параллельно по фикстурам 01.3. 04.5 (лендинг) независим и может выполняться внешним исполнителем.

Общие правила для всех UI-задач этапа:
- Читать: [DESIGN.md](../DESIGN.md) (утверждённое направление), образцы `identity/compositions/*.svg` и их превью, токены `identity/tokens/tokens.css`, а также общие требования VibeMachina о визуальной основе, анти-шаблонах, UX, системе и базовом движении, которые MAIN передаёт в пакете задачи.
- Использовать только `--nv-*` токены и примитивы 04.1; недостающий общий примитив запрашивать у MAIN, а не создавать локальную копию.
- Каждая поставка экрана включает композицию, тексты из каталога строк, все состояния (пусто, ввод, ожидание, успех, сбой, прерывание), hover/focus/pressed/selected, клавиатуру, узкий экран 360 px и reduced motion. Это часть готовности, а не отдельная «полировка».
- Строки фичи лежат в `web/src/features/<фича>/strings.ts` (русский); общие в `web/src/i18n/ru.ts` (владелец 04.1).
- Проверка агентом: типы, сборка, юнит-тесты логики (Vitest + Testing Library для поведения компонентов без браузера), статический просмотр CSS и разметки. Внешний вид и понятность проверяет пользователь (TESTING.md). Браузерная автоматизация запрещена.

Завершение: 04.1–04.5 приняты; на фикстурах и затем на реальном сервисе (05.1) работают S04, S05 (интерфейсная часть), S06 (отображение), S11, S12.

## 04.3 Разбор проверки: вердикт, эпизоды, видео, лента, решения и пересчёт
Status: todo
Requirements: R02, R03, R04, R05, R06, R21, R26, R27
Depends on: 04.1
Owner: SUBAGENT frontend
Paths: web/src/features/review/, web/tests/review/

**Запуск и параллелизм:** нужны примитивы 04.1. Параллельно с 04.2 и 04.4. На реальном сервисе подключается в 05.1.

**Результат:** главный экран продукта. Проверяющий видит вердикт, переходит по эпизодам, смотрит нужные секунды и кадры с разметкой, читает «что видно» и норму, принимает решение, поправляет роль и сразу видит, что изменилось.

**Композиция:** по образцу `identity/compositions/workspace-desktop.svg`: полоса вердикта с «Лист проверки»; слева сцена (видео 16:9, управление, переключатель «Разметка», лента фактов), справа колонка эпизодов 400–420 px с собственной прокруткой; внизу колонки «Без замечаний: N правил» (`Disclosure` со списком правил и статусами, включая «нельзя проверить» с окнами). Узкий экран по `workspace-mobile.svg`.

**Поведение:**
- При открытии выбран первый эпизод, видео стоит на его `timecode_sec`, на кадре разметка. Без эпизодов: «Нарушение не обнаружено», список проверенных правил и непроверяемые участки.
- Выбор эпизода (клик в списке, клик по окну на ленте, стрелки вверх/вниз в списке) перематывает видео, окно эпизода скользит на новое место (220 ms), карточка раскрывается, остальные сворачиваются. Кадры-доказательства: клик ставит видео на кадр; «Открыть кадр» показывает полный размер в `Dialog` (с оверлеем и без).
- Решение: `SegmentedChoice` «Подтвердить / Не нарушение / Не видно на записи»; сохраняется сразу через `PUT …/decision` с текущей ревизией; рядом «Сохранено» или ошибка с «Повторить»; заметка сохраняется по потере фокуса и по Ctrl+Enter; «Не нарушение» переводит метку в серую пунктирную и может изменить вердикт (с объяснением в полосе вердикта: «Вердикт с учётом ваших решений: …»; автоматический вердикт виден рядом мелко).
- Уточнение роли: клик по рамке человека на видео (или выбор в списке «Люди в кадре» в колонке, если рамку трудно поймать) открывает `Popover` «Кто это на записи?» с `RadioList` ролей и кнопкой «Пересчитать по нормам». Ответ `reevaluate`: список и лента обновляются, изменённые эпизоды получают плашку «изменено», удалённые сворачиваются с пояснением, полоса вердикта говорит, изменился ли вердикт. Для примера используется `dry_run` и пояснение «В примере изменения не сохраняются».
- Конфликт 409: `InlineNotice` «Эту проверку только что изменили в другой вкладке» с «Обновить», заметка в поле сохраняется.
- Клавиатура: пробел воспроизведение и пауза, `[`/`]` шаг кадра, стрелки по эпизодам, `1/2/3` решение для выбранного эпизода (подсказка в «Горячие клавиши»).
- Видео недоступно (истёк срок хранения, 410): сцена показывает кадры-доказательства и сообщение «Исходная запись удалена по сроку хранения. Кадры и решения сохранены.».
