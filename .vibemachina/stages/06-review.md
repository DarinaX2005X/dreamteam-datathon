# 06 Код-ревью и стабильность
Status: todo

Цель этапа: независимо проверить, что продукт выполняет исходную задачу (BRIEF), подчиняется утверждённым контрактам и выдерживает реальное использование, и исправить подтверждённые дефекты. Это обязательный этап плана, а не необязательная проверка. Он начинается после интеграции и устойчивости (05.2) и заканчивается, когда подтверждённые дефекты исправлены и перепроверены.

Правила ревью: первый проход выполняет исполнитель без контекста реализации и планирования, читая только BRIEF, код и команды запуска, без REQUIREMENTS, PROJECT, DESIGN, PLAN, PLAN-HUMAN и файлов этапов. Затем тот же исполнитель получает контракты для второго и третьего вопросов. Проверки ведутся по коду, домену, HTTP и API; браузерная автоматизация и снимки экрана запрещены. Ревьюер ничего не правит и возвращает находки MAIN, который записывает их в этот файл (раздел «Находки» в 06.3).

## 06.2 Проверка контрактов, норм и реального использования
Status: todo
Requirements: R24, R06, R09
Depends on: 06.1
Owner: SUBAGENT to assign
Paths: none

**Запуск:** тот же ревьюер после возврата находок 06.1 получает PROJECT, DESIGN, PLAN, этапы, общие требования VibeMachina к UI (основа, анти-шаблоны, UX).

**Что проверяется:**
- Контракты: C-API-V1 побайтно по ключам, C-ERR коды, C-UI-API ответы, C-DATA (`timecode_sec == evidence[0].timestamp_sec`, 1–3 кадра), вердикт и ревизии (API отдаёт ревизию 1), C-STORE (аренда, повтор, удаление по сроку, исключение `data/` из обучения), C-CONFIG (секреты не в git), C-LANDING (стили изолированы, нет зависимостей от `web/src`).
- Нормы: каждое правило ссылается на существующий `clause_id`; цитаты показаны только сверенные; описания строятся шаблоном из фактов и не содержат утверждений о суммах, документах, мотивах; при `Coverage` правило не создаёт эпизод.
- Реальное использование: S01–S12 по коду и API; изменение роли меняет результат и сохраняет решения; повторная отправка не дублирует; перезапуск не теряет; 5 параллельных заданий укладываются; офлайн-запуск.
- UI в коде: все состояния присутствуют, focus-visible, hover под fine pointer, reduced motion, 360 px без горизонтального переполнения, нет сырых HEX вне токенов, нет текстов-отчётов о разработке, нет выдуманных метрик на лендинге.
