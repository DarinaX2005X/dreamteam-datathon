# Обучение моделей Lado

В проекте есть два направления: детектор рук и предметов и временная модель
поиска эпизодов. Обучение, обработка кадров и проверки моделей выполняются
в приватном рабочем пространстве Modal на L4 24 ГБ. Конфигурация размещения —
в [deploy/MODAL.md](../deploy/MODAL.md).

Данные, разметка, кэши и веса исключены из Git. В рабочее пространство обучения
передаётся только разрешённая development-часть. Финальный holdout хранится
отдельно и не используется для выбора модели или порогов.

## Детектор рук и предметов

`train_objects.py` обучает RT-DETRv2 на проверенной рамочной разметке четырёх
классов: `hand`, `cash`, `identity_document`, `money_counter`. Входные кадры
разделяются по исходным видео: соседние кадры одной записи не могут попасть
одновременно в обучение и внутреннюю проверку.

Правила разметки:

- Обводить видимую кисть, а не всю руку или человека.
- Отмечать отдельные купюры и пачки денег, включая пачку с бумажным держателем.
- Снятый бумажный держатель не считать деньгами или удостоверением.
- Удостоверение отмечать по различимой карточке; цвет прямоугольника сам по себе
  не определяет его класс.
- Отличать счётчик банкнот от соседних приборов, ноутбуков и шкафов.
- Проверять все целевые классы на кадре. Неуверенные области сохранять в
  `ignore_boxes`; этот рецепт исключает такие кадры целиком из обучения и оценки.

Формат приватной разметки:

```json
{
  "schema_version": 1,
  "classes": ["hand", "cash", "identity_document", "money_counter"],
  "annotations": [{
    "source_sha256": "<SHA-256 исходного видео из train-части>",
    "timestamp_sec": 1.0,
    "width": 464,
    "height": 848,
    "remote_frame": "/private/object-labels/<набор>/<кадр>.png",
    "label_source": "assistant_manual_review",
    "reviewed_classes": ["hand", "cash", "identity_document", "money_counter"],
    "objects": [{"kind": "hand", "bbox_xyxy": [100, 200, 120, 225]}]
  }]
}
```

Координаты рамок заданы в пикселях исходного кадра. `label_source` отражает
происхождение разметки; автоматические предложения локализатора не заменяют
проверенные метки. Загрузчик проверяет принадлежность исходника разрешённой
части, уникальность кадра и границы каждой рамки.

Запуск из корня проекта с настроенным Modal:

```bash
python -m modal run -m deploy.modal_object_training --stage preflight
python -m modal run -m deploy.modal_object_training --stage train \
  --run-id <новый-идентификатор> --annotations <приватный-файл-разметки>
python -m modal run -m deploy.modal_object_training --stage calibrate \
  --run-id <идентификатор-завершённого-обучения>
```

Детектор видит полный кадр и перекрывающиеся фрагменты; обучающие приближения
содержат исходные пиксели. Зрительная основа обучается с меньшим шагом, а
статистики BatchNorm фиксированы для небольших пакетов кадров. Пороги классов
подбираются на внутренней проверке и фиксируются до проверки на отдельных
development-видео. Метрики сопоставляют рамки при IoU 0,5, отдельно учитывая
пропуски и ложные обнаружения каждого класса.

`deploy.modal_object_validation` проверяет выбранный checkpoint на отдельной
разметке development-validation. `deploy.modal_object_upscale` сравнивает
исходные фрагменты, обычное увеличение и Real-ESRGAN. Увеличенные изображения
служат входом экспериментальной модели; доказательства сохраняют исходные кадры.

Экспорт выбранных весов выполняется отдельным действием:

```bash
python -m modal run -m deploy.modal_object_training --stage export \
  --run-id <завершённый-запуск> --model-id lado-objects-<версия>
```

Экспорт сохраняет веса в приватном томе моделей и возвращает запись манифеста
с SHA-256 и порогами. Подключение через `NAVIDU_OBJECT_MODEL` выполняется после
проверки качества. Экспорт сам по себе не изменяет работающий сайт.

## Временные модели

`train_proposal.py` поддерживает InternVL3.5-4B и Qwen3-VL-4B-Instruct с LoRA;
каждая модель использует собственный процессор изображений. Альтернативный
`train_temporal.py` обучает временную сеть на замороженных зрительных признаках.
Они предлагают время эпизода для проверки основным конвейером фактов и правил.

Разбиение задаётся в `eval/training-splits.json`. Загрузчик проверяет SHA файлов.
Имена файлов и правильные ответы не входят во вход модели. Каталог запуска
должен быть новым; лимит времени включает обучение, оценку и сохранение.

`progress.json`, `run-manifest.json` и приватные checkpoints фиксируют состояние
запуска. `selected_epoch: null` означает отсутствие принятого улучшения.
Числовые результаты экспериментов хранятся в `eval/reports/`, рабочие результаты —
в исключённых из Git каталогах. Ни один тренер не публикует модель автоматически.
