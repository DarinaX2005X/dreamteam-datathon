# Обучение поиска кандидатов

Обучение выполняется только на разрешённом Brev `fierce-aquamarine-beaver` с NVIDIA L40S. Оно предлагает время подозрительного события; окончательный тип нарушения и норму определяет проверяемый конвейер фактов и правил. Выбор checkpoint сам по себе не включает его в приложение.

Разбиение фиксировано в `eval/training-splits.json`: 24 уникальных train-видео, 8 inner-validation, 8 нетронутых holdout. Загрузчик проверяет SHA файлов. Имена файлов и правильные ответы не входят во вход модели. Ручная книга разметки дополнительных типов пока не потребляется этими тренерами.

## Измеренный LoRA-пилот

`train_proposal.py` использует InternVL3.5-4B, PEFT q/v rank8, замороженную зрительную часть, bf16, 16 кадров при 2 fps. В первом запуске одна эпоха из 144 окон и 18 шагов оптимизатора вместе с проверками заняла 347.04 с. На 8 inner-validation источниках TP4/TN1/FP3/FN0 стали TP4/TN0/FP4/FN0; средняя ошибка времени выросла с 12.75 до 17.5 с. Этот checkpoint отклонён и не активирован. Числовой отчёт: `eval/reports/l40s-proposal-pilot.json`.

## Вариант с замороженными признаками

`train_temporal.py` проверяет закреплённые версии зависимостей и хеши исходной 4B-модели, затем извлекает признаки каждого кадра при 2 fps. Признаки объединяют среднее по изображению и четыре пространственные области; фиксированная случайная проекция уменьшает размер до 256. Нормализация рассчитывается только на train.

Обучается небольшая временная сеть из трёх свёрточных слоёв. На вход поступают признаки и их изменения между соседними кадрами. Потеря использует бинарную метку всего видео и мягкую цель вокруг известного момента положительного события; остальные кадры положительного видео не объявляются отрицательными. Порог 0.5, максимум 30 эпох, остановка после пяти эпох без принятого улучшения. Подбора порога по validation нет.

Пример команды внутри подготовленного контейнера:

```bash
python training/train_temporal.py \
  --base-model /app/models/internvl3_5-4b \
  --models-dir /app/models \
  --dataset-dir /workspace/data/dataset \
  --native-baseline /baseline/baseline-validation.json \
  --output-dir /output \
  --max-wall-minutes 90
```

Каталог `/output` должен быть новым или пустым. Внутренний лимит включает проверку весов, кэширование, обучение и validation; последняя минута резервируется для сохранения. Внешний supervisor ограничивает жизнь именно контейнера эксперимента. Доля CUDA allocator ограничена 0.70 для совместной работы с приложением.

Выбор требует сохранить каждый ранее правильный бинарный ответ и исправить хотя бы один ошибочный. При неизменных бинарных решениях нужно улучшить среднюю ошибку времени не менее чем на 0.5 с на том же наборе положительных источников. Невалидные и нечисловые результаты не принимаются. Это правило выбора на восьми development-источниках, а не доказательство точности на новых камерах.

`progress.json` и `progress.jsonl` содержат числовые стадии, счётчики, время и память. Кэш, проекция, checkpoint перед каждой validation, выбранные веса и конфигурация сохраняются отдельно с SHA. `selected_epoch: null` означает, что исходный вариант следует сохранить. Все данные, кэши и веса остаются в исключённых из Git каталогах.
