# Собственный пример Lado

В репозитории нет готовой демонстрационной записи. Кнопка примера скрыта, пока
`NAVIDU_EXAMPLE_CHECK_ID` не указывает на завершённую проверку с подтверждённым
автоматическим анализом и признаком `is_example`.

Создавайте пример только из собственной записи пользователя или команды.
Материалы организаторов, включая переименованные копии, использовать для этого
нельзя. Команда сверяет SHA256 с `research/dataset/inventory.csv`, если он доступен.
Дополнительные списки можно передать через `--organizer-inventory path/to/inventory.csv`;
в них нужен столбец `sha256`. Эта проверка распознаёт известные исходники, а
`--own-recording` фиксирует явное подтверждение происхождения записи оператором.

1. Установите зависимости API и обычного обработчика, подготовьте локальные веса
   и проверенную конфигурацию модели согласно основному README. Запустите сервис
   с обработчиком. `/api/ui/health` должен возвращать `ready: true`,
   `analysis_ready: true`, `analysis_mode: "validated"`. Загруженных весов и
   диагностического режима недостаточно. Команда не скачивает модели, не запускает
   вторую копию модели и не обходит проверку готовности.
2. Из корня проекта выполните команду Python из окружения API:

   ```powershell
   .\backend\.venv\Scripts\python.exe scripts/build_example.py --video "C:\team-recordings\own-demo.mp4" --own-recording
   ```

   На Linux используйте `backend/.venv/bin/python` и локальный путь к собственной
   записи. Команда читает ту же `.env`, что и `scripts/run_local.py`; уже экспортированные
   переменные имеют приоритет. `NAVIDU_DATA_DIR` должен совпадать с каталогом
   работающего сервиса. Ограничения размера, длительности и формата обычной загрузки
   действуют также для примера.
3. Команда копирует запись в хранилище сервиса, сохраняет подтверждение происхождения
   в `data/checks/<id>/example.json` и ставит проверку в обычную очередь. Её выполняет
   тот же локальный `Worker` через `RealPipeline`; применяются обычные правила
   версионирования, кеша, проверки модели и публикации доказательств.
4. Только после успешного проверенного анализа команда выведет:

   ```dotenv
   NAVIDU_EXAMPLE_CHECK_ID=<полученный идентификатор>
   ```

   Добавьте эту строку в `.env` и перезапустите API. Скрипт не изменяет `.env` и
   не включает пример самостоятельно. При неготовой модели, ошибке анализа или
   истечении ожидания эта строка не выдаётся. `--wait-seconds` меняет время ожидания
   (по умолчанию 1800 секунд); прерывание ожидания не отменяет очередь.

Пример помечается `is_example` при постановке в очередь. Решения, заметки, сохранённый
пересчёт, отмена и повтор через API для него запрещены. Предпросмотр пересчёта доступен
без сохранения изменений. Исходное видео и результаты примера не удаляются обычной
политикой хранения. Публичного API удаления проверки нет. Чтобы убрать кнопку,
удалите `NAVIDU_EXAMPLE_CHECK_ID` из `.env` и перезапустите API; сами данные при этом
сохраняются.

Проверки в тестах используют явно синтетические входы только для очереди, хранения
и прав доступа. Они не подтверждают качество распознавания действий и не создают
производственный демонстрационный пример.
