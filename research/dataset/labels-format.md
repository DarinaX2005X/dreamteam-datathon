# Реальный формат датасета

Проверено локально 17.10.2026. Источник — `open.zip`, предоставленный пользователем из Downloads. Исходные видео и книга хранятся только в игнорируемой `data/dataset/`; архив, видео и кадры не публикуются. Ни видео, ни кадры не отправлялись во внешнюю модель или в инструмент просмотра изображений.

## Книга организаторов

`open/open_labels.xlsx`, 5701 байт, SHA256 `4faf595a2679c2f8b2b41be041de59bb3c11cd6e77d57226f1cbcc14b2cc3e75`.

Единственный лист `labels`, 43 строки с заголовком, 3 столбца. Заголовки и примеры ниже переданы буквально:

| наименование файла | таймстемп | нарушение / без нарушения |
| --- | --- | --- |
| X-1 | 22 секунда | нарушение |
| X-2 | 10 секунда | нарушение |
| Х-3 | *(пустая ячейка)* | без нарушения |
| Х-4 | 57 секунда | нарушение |
| Х-47 | 1минута 8 секунда | нарушение |

В `X-1` и `X-2` используется латинская `X` (U+0058), в остальных именах — кириллическая `Х` (U+0425). Нормализация визуально похожих букв запрещена: идентификаторы и имена файлов совпадают посимвольно.

Всего 42 записи: 22 «нарушение», 20 «без нарушения». У положительных ровно один таймстемп в каждой строке, у отрицательных ячейка пуста. Типы событий, интервалы, рамки предметов, роли людей и нормы в источнике **отсутствуют**. Эти данные нельзя выдавать за разметку организаторов.

`eval/labels.csv` имеет контракт `video_id,has_violation,label_sec,type_code`: двоичная метка 0/1; время в секундах от начала записи; пустое время для отрицательного видео; `type_code` оставлен пустым. `1минута 8 секунда` преобразовано в `68.0`. Конвертер отвергает неизвестные заголовки, неизвестные значения, формулы, неверный формат времени, повторный video_id и несовпадение набора файлов.

## Фактические видео

- 42 MOV, 40 различных последовательностей байтов, общий объём 292.871 MB (десятичные MB).
- Все H.264, 464 × 848 пикселей, без аудиопотока, поворот из метаданных отсутствует (`rotation=0`).
- Длительность 11.633–142.533 с; медиана 22.667 с; суммарно 1444.163 с с учётом копий.
- Средняя частота 29.758065–30.0 fps, `r_frame_rate=30/1`. Для таймкодов следует применять PTS, а не номер кадра / 30.
- Все исходные метки лежат внутри длительности соответствующего файла.

Декодированные PTS отдельно проверены у X-1, Х-3, Х-14 и Х-28: 6140 кадров, интервалы от 0.033333 до 0.066667 с, суммарно 11 интервалов длиннее 0.04 с; временные отметки строго возрастают. Это реальная переменная частота кадров, а не только округление fps. Команда повторения: `python research/dataset/timing_probe.py`; сохранённый результат — `timing-check.json`.

Полный машинный результат: `research/dataset/inventory.csv`, агрегаты: `inventory-summary.json`. Поле `file` относительно `data/dataset`; временные абсолютные пути в отчёт не записаны.

## Дубликаты и оценка

| Одинаковые файлы | SHA256 | Метки |
| --- | --- | --- |
| Х-4, Х-47 | `5385be9420e6a70547d6bcfd0b13d60f9c0738877645afa277d09550a96b8445` | Положительные; разные времена 57 с и 68 с |
| Х-5, Х-48 | `1f5840bff58f298e89c4afa00cb1c18f6dafc5c4096c251d9b507604ebefe906` | Обе отрицательные |

Х-4 и Х-47 не противоречат друг другу по вердикту. Две временные метки сохраняются вместе как исходные аннотации одного видео; пока человек не проверил события, нельзя решить, это два эпизода или расхождение разметки. Нельзя молча выбрать одну метку либо утверждать, что оба типа/эпизода подтверждены.

`eval/source-labels.json` объединяет копии по полному SHA256 и хранит `label_secs: [57.0, 68.0]` плюс происхождение каждой метки. Эта группа имеет `timing_ambiguous: true` и исключается целиком из основной оценки таймкода; две метки не считаются двумя подтверждёнными событиями. `eval/folds.csv` даёт 5 воспроизводимых фолдов по 8 **уникальных источников**; копии никогда не попадают в разные фолды. На уровне источников 21 положительная и 19 отрицательных записей. Разбиение по имени файла было бы утечкой. Фолды 1–4 используются для разработки, fold 0 зарезервирован для итоговой проверки после заморозки конвейера. Фолды не доказывают независимость актёров, декорации или ракурса; оценка нового ракурса требует отдельной записи.

## Воспроизведение

Из корня репозитория, Python 3.10+ и `ffprobe` в PATH:

```text
python research/dataset/extract_archive.py /path/to/open.zip --output data/dataset
python eval/convert_labels.py data/dataset/open/open_labels.xlsx --videos-dir data/dataset/open/videos
python research/dataset/inventory.py --dataset-dir data/dataset
python eval/make_splits.py
python -m unittest eval.test_convert_labels -v
```

Скрипты используют только стандартную библиотеку Python; XLSX читается из Office Open XML без установки Excel или конвертации через облачный сервис. На текущем наборе 8 тестов прошли, включая реальные 42 строки, отсутствие утечки между копиями, отказ от обхода каталога при распаковке и сохранение существующих файлов. Это проверка данных и конвертации, **не метрика качества модели**.
