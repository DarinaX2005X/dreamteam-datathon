# Ручная типовая разметка

Готовая частная книга: `data/annotations/lado-annotation.xlsx`. Каталог `data/` игнорируется Git. В книге четыре видимых листа: инструкция, словарь, 32 уникальных источника разработки и пустая таблица дополнительных эпизодов. Восемь отложенных источников и их примеры не включаются.

Серые столбцы A:I основной таблицы сохраняют бинарные/временные метки организаторов, алиасы копий, SHA, фолд и путь. Тип организаторами не указан и остаётся пустым. Эти столбцы защищены от случайных изменений. Человеческие поля J:R изначально пусты; исходный 0 не превращается в `NONE`.

Просмотрите запись целиком, выберите один основной тип и запишите только видимые факты. Время задаётся числом секунд от начала исходного файла: начало ≤ опорное время ≤ конец. Несколько эпизодов или типов записываются отдельными строками на листе «Эпизоды». Не объединяйте коды в одной ячейке. Для `OTHER` и `UNCLEAR` обязателен комментарий; `V-OUTSIDER` является только наблюдением входа в установленную зону хранения, а не положительной меткой нарушения.

`sufficient_visible`, `candidate`, `unclear` означают полноту видимого основания, не юридическую истинность. Если не видно ключевого обязательного факта, нужен `UNCLEAR`, а не достаточный положительный класс со словом «возможно». `NONE` допустим после содержательного просмотра при пригодном обзоре; плохое качество само по себе не даёт `NONE`.

Словарь хранится в `dictionary.json`, проверен по `rules/sources/S231.yaml` и отдельно согласован с нормативным review. Он не копирует отключённые/необоснованные автоматические условия. Для `V-COUNT-ABSENT` сохранён текущий смысл приёма денег по п.20; иной случай выдачи по п.31(4) не расширяет этот код автоматически. Никакие произвольные 2/3/5/60 секунд не считаются нормативным порогом.

Создание новой книги (нужен `openpyxl`):

```text
python eval/annotation/build_workbook.py
```

Генератор **никогда не перезаписывает** существующую книгу, включая начатую разметку. Для другой копии используйте `--output data/annotations/lado-annotation-copy.xlsx`. Время, исходные столбцы, допустимые коды и обязательные комментарии можно проверить без изменения книги:

```text
python eval/annotation/build_workbook.py --validate-only --output data/annotations/lado-annotation.xlsx
```

Проверка новой пустой книги дополнительно принимает `--require-empty`. Проверяется повторное открытие файла, ровно 32 development-источника, неизменность исходных данных, отсутствие holdout, пустые первоначальные типы, отсутствие формул в ячейках и корректность заполненных человеческих полей. Выпадающие списки и подсветка помогают вводу; итоговый валидатор обнаруживает ошибки, которые Excel может пропустить при вставке диапазона.

Книга не подключена к обучающему reader и не меняет `eval/labels.csv` или `eval/training-splits.json`. Текущее обучение продолжает использовать исходную бинарную/временную разметку. Новая человеческая разметка потребует отдельной проверки и явного решения об использовании. Кадры, автоматические описания и прогнозы модели в книгу не добавляются. Визуальную проверку и просмотр видео выполняет пользователь.
